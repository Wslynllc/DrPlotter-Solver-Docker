# Agents in DrPlotter-Solver-Docker

Read README.md and the Dockerfile before changing anything. The repository is those two files plus
`.github/CODEOWNERS`; the Dockerfile is the whole build.

- Shared standards win: `Wslynllc/project-standards` (`README.md`, `Owner approval.md`, `Delivery gates.md`,
  and `Native-first infrastructure.md` for how solver nodes reach the tailnet). This file only adds this
  repository's values.
- Merging changes what later deploys, and only by hand. No workflow, Makefile or flag exists (`.github/` holds
  only CODEOWNERS), so nothing builds, publishes or deploys on merge. The published image
  `rmkr/drsolver_node:latest` (README.md) is built and pushed manually; a merged Dockerfile change reaches
  rented hosts only after someone rebuilds and pushes it.
- Owner tap (`rkroelin-yes`) is required only for `/.github/` (see `.github/CODEOWNERS`; no default owner).
  Everything else, including this file, merges after an independent agent review. Do not add or change
  CODEOWNERS here: it is a permission change.
- No offline check exists: no Makefile, test script or CI. Do not invent one or report a build as passing
  unless you ran it. `docker build` needs the network (base image, Tailscale installer), so it is not offline.
- Before a push, `git diff --check` and `trufflehog git file://$PWD --no-update --no-verification` must find
  nothing.
- `TAILSCALE_AUTHKEY`, `DRSERVER_IP_ADDRESS` and `DRPLOTTER_CLIENT_TOKEN` come from the host's environment
  (README.md). Never put values in git, logs, PRs or evidence. Known open defect: the generated entrypoint
  prints the client token to the container log (Dockerfile, issue #3); do not copy that pattern.
- The entrypoint is generated by one `echo '...' > /entrypoint.sh` in the Dockerfile, so every line of it but
  the last ends in `\n\`. Keep that escaping, and keep README.md's CRLF line endings and BOM so diffs stay small.
- The base image is pinned: `ghcr.io/foxypool/drplotter:1.0.4-solver` (Dockerfile, README.md). Changing the tag
  changes the solver version; say so in the PR.

## Where context lives

- `README.md`: purpose, the Docker Hub image, the three environment variables.
- `Dockerfile`: base image, Tailscale and proxychains install, userspace networking, the inline entrypoint with
  its boot-time health checks.
- Tailnet access (tags, ACLs) for solver nodes is not defined here. Tailnet changes go through
  `Wslynllc/tailnet-policy`; whether it already covers these nodes is unknown.
- Related and unknown: the DrServer these nodes connect to is not in this repository (location unknown).
- Kanban: no lane board for this repository; standards work across repositories runs on the `repo-standards`
  board.
